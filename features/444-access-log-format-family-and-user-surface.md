# Feature: Access log format family, populated-field detection evidence, and the user surface

## Status

- **Issue:** #444. One work package: the format family, the detection signal, the user surface, and the defects found while specifying them all ship under this issue (architect, 2026-09-03).
- **Phase:** specification. No branch cut, no code. Decisions below are marked PROPOSED until the architect locks them; a locked decision is restated as `Dn — LOCKED (date)`.
- **Record:** this file. The issue body is its snapshot. Findings from the 2026-09-03 investigation (four audits, each independently verified) are in § Findings; the raw captures live in the session scratchpad and are not committed.
- **Governing records:** `features/log-format-registry.md` § Drop 1.5 (variant groups D44–D53, weights I1, ordering F1, mechanism N1–N10) and its two `-V` section contracts; `features/58-format-registry-staged-detection.md` (load-time gates D24, pinned-closure ordering D26, guards D28, one generated scan sub D39/D40); `features/user-defined-metrics.md` (counting aggregations, the sessions oracle); `features/503-yaml-aggregate-export.md` (export keys); `features/column-layout-refactor.md` (dynamic columns); `tests/HARNESS-DESIGN.md`.

## Motivating consumer

Analysing access logs from applications other than the ThingWorx Tomcat configuration with the same techniques that work today on it: concurrency per time bucket, narrowing to one actor, seeing who drives a hotspot. Apache HTTP Server fills the remote-user column; Tomcat rarely does; the ThingWorx and Windchill Method Server formats already carry a user that nothing reads. The analyst should get the same user column, the same filtering and the same highlighting from every format that carries a user, and should see a format name that says what the file is rather than which product the first specimen came from.

## Requirements (architect's terms, 2026-09-03)

### A. The access-log format family

- **R1.** The access-log formats carry an industry-standard root name, not a product name. The shapes are not specific to Tomcat or Apache HTTP Server. `tomcat_access_common` is the wrong name; the others have the wrong base name too.
- **R2.** Variants extend the root and are named for what they add. `tomcat_access_with_duration` is named for one custom configuration and is wrong twice: it is not Tomcat-specific, and it actually carries optional thread and session tokens. Each shape is a named format so a matched file is identified correctly: time only; time plus thread plus session; and the CodeBeamer bracketed form.
- **R3.** The generic and default shapes exist as named formats: the industry common and combined formats, and the shipped defaults of Tomcat, Apache HTTP Server and nginx.
- **R4.** The formats form one family (group) with many variants.
- **R5.** The CodeBeamer pattern recognises its two bracketed duration tokens generically: a number with an optional decimal part followed by a unit, twice, where the unit may be microseconds, milliseconds or seconds.
- **R6.** "The inverted one for the CodeBeamer configuration" in the issue body was a mistake and is dropped.

### B. Detection

- **R7.** A declared field that is present and populated in the sampled lines is a confidence signal and counts in the ranking that chooses between formats.

### C. The user surface

- **R8.** The remote-user column of access logs is captured. The captured `user` of the ThingWorx standard format and of the Windchill Method Server format, unused today, becomes consumed by the same surfaces. Every format that carries a user exposes it the same way.
- **R9.** Filtering in and out works on the user, not only the message part of the line.
- **R10.** Distinct users per time bucket are counted and rendered the way the sessions column is, bar graph included, with highlight support.
- **R11.** User and session columns are shown together when both have source data.

### D. Defects to fix under this issue (architect, 2026-09-03)

- **R12.** Whatever is captured as a metric is exported and output. The highlighted-sessions value is computed and reported in one verbose section only; it reaches neither the STATS CSV nor the YAML export, although the export record documents it.
- **R13.** The mid-line quoted `"-"` of a combined-format line must never be captured as a session or a thread. Today a combined line without a duration binds the duration variant through its all-optional tail, counts `"-"` as a session, and prepends user-agent fragments into message keys.
- **R14.** A bare `-` in the session or thread position is an absent value, never a session or thread, on every surface (column, message identity, highlight).
- **R15.** The variant-ambiguity note is correct for groups of more than two members and is reported for every file that fell to a default, not once per run.
- **R16.** Every comment, harness assertion and document that still describes the Tomcat and httpd pair as unsplit and "pending the registry rewrite" is trued up; the test-log inventory (`docs/test-logs.md`) is trued up to the corpus: the two unlisted access-log files, five servers rather than four in the large set, and the shape change part-way through that set.
- **R17.** The mixed `0us` / `ms` rendering seen on the thread-plus-session shape is traced to its cause and fixed. The architect's reading is that the shape is being misattributed to the CodeBeamer format; the investigation measured the shape binding `tomcat_access_with_duration` on every line (517,684 matched, 0 unmatched), so the cause is established during the fix, not assumed.

## Findings (2026-09-03 investigation; what was measured, on what, and what the reader would observe)

### Corpus (`logs/`, read-only)

- **F1 — Six access-log shapes exist locally, in two directories.** A content scan of every file under `logs/` (head of 33,482 files) found access-log-shaped lines only under the access-log and CodeBeamer directories: 160 files. Shapes: (A) httpd common plus integer microsecond duration, 11 whitespace fields; (B) Tomcat common plus integer millisecond duration, 11 fields, 90 of the 150 files in the large set; (C) common plus fractional duration plus thread name plus session id, 13 fields, 60 of the 150 files, switching from (B) on one date on all five servers; (D) an nginx custom format: combined plus a quoted forwarded-for plus six `key="value"` pairs carrying a decimal-seconds request time; (E) CodeBeamer, common plus `[Nms] [N.NNNs]`; (F) one corrupt file with concatenated records.
- **F2 — The remote-user column is populated on 4 lines in roughly 2.5 million.** Shape A: 1 of 2,696 and 1 of 677; shape D: 2 of 219,933; shapes B, C, E: zero. Two distinct values, both administrative accounts. No file has both a populated user and a thread or session tail.
- **F3 — Session and thread always co-occur in shape C.** Session populated 34–83 % of lines per file (354–5,443 distinct per file); thread present on 100 % of lines, shape `https-jsse-nio-<port>-exec-<N>`; one file carries 198 malformed-request lines whose thread token is the literal `null`.
- **F4 — Shape C's duration is fractional**: 106,652 of 107,350 tokens carry a decimal point (three places), median 34.217, max 185,744 on one file. The inventory assigns the large set "milliseconds".
- **F5 — CodeBeamer's two bracketed values agree on every line**: 741 of 741 lines, the millisecond integer equals the seconds value × 1000. Consistent with a Tomcat ≤ 9 valve pattern `[%Dms] [%Ts]` (F14). No public source documents the CodeBeamer pattern; the vendor's Tomcat-configuration page carries no access-log valve and its wiki needs a login.
- **F6 — What the tool binds today, per shape** (`-bs 1440 -oe -V format-detection`): A → `tomcat_access_with_duration` by tie on the default at confidence 0.50, durations read as milliseconds where the producer wrote microseconds (top-message medians render as minutes), note printed. B → the same slug at 0.75 by default, note printed. C → the same slug, 517,684 matched, 0 unmatched, sessions column correct (468 rendered, 468 counted independently), thread name folded into every message key as a bracketed prefix, and the mixed `0us`/`ms` rendering (R17). D → `httpd_access_with_duration` by filename evidence (the file is named the httpd way), no duration read at all, and a spurious sessions column of 18 and 3 (R13). E → `tomcat_codebeamer`, and the verbose section prints an `access_with_duration` group verdict for a file that never bound that group. F → renders no sessions column and shows the same mixed units.
- **F7 — Filename evidence is absent for 158 of the 160 files**, because the analyst-renamed stems (`localhost_access_log-<host>.<date>.txt`) defeat the stem match; only the corrupt file and the nginx file carry usable name evidence.

### Registry and detection (`ltl`)

- **F8 — The host, ident, user prefix `([^ ]+ ){3}` is shared by all five access entries and none captures the user.** Perl keeps the last repetition, so capture 1 already holds the user token with its trailing space at match time; the generated block assigns it to `undef`. The comment above `format_registry_specs()` requires the prefix to stay backtracking-free because the patterns are attempted and mostly fail on every access-log line. The development-tier benchmark for this path is `single-day-access-log` (std); the two monthly access-log tiers are release instruments.
- **F9 — Bytes-only lines never reach the duration entry**: `tomcat_access_common` (`$`-anchored) is ordered ahead and claims them. The genuine overload is four shapes that all bind `tomcat_access_with_duration`: integer duration, fractional duration, plus thread, plus thread plus session. Measured on synthetic files: fractional durations survive to display; a literal `-` session is captured (and prepended as `[-]` under `-xs`); a populated user changes nothing on any surface.
- **F10 — The all-optional tail is the defect mechanism behind R13.** Replaying the exact pattern on an nginx combined line captures duration undefined, thread `"-"` and session `"-"` (quote characters included), which passes the sessions guard (`ne "-"`) and is counted. The pattern would also claim JBoss lines; only static ordering (derived ancestors `mt12, mt4, mt9`) prevents it. The staged-detection record already names all-optional tails as "the mt3 lesson".
- **F11 — Only same-pattern variant members are implemented.** The scan array holds one occupant per group; a member with a different pattern is built and validated but never enters the scan and is reachable only if evidence seats it (proven by splicing a third member with a distinct pattern: slot count unchanged, member absent from occupants). The Drop 1.5 decision text says different-pattern members "enter the scan as ordinary entries"; the mechanism note N1 describes what the code does. New shapes reachable by content must therefore be their own scan slots, declared ahead of the generic shape, with the generic entry's declared ancestors grown to name them, or the build dies at the cross-shadow gate.
- **F12 — No content probe runs on the access family.** Both probe emission points are gated on ISO time layouts; the five access entries declare `apache_clf`, so the steady loop carries no probe and the verbose `probes:` row is all zeros. The sample pass keeps only the timestamp capture; the variant selector re-matches every sample line against every member's pattern in boolean context and discards the captures. A populated-field signal has one clean home: the selector's match loop, reading captures it already produces. The evidence weights are one hash in the globals (`shape 1.0, stem 3.0, ext 1.0, filename_date 0.5, index 0.25, group_default 1.0, mono_per_violation 0.5, mono_cap 1.0`); a new class is one more key there, per the locked rule that weights never live in the registry schema.
- **F13 — The sample's per-entry counts name the group default, never the selected member**, because sampling runs before selection. A probe fed from those counts would attribute observations to the default.
- **F14 — Producer conventions (primary sources).** Tomcat: `common` is `%h %l %u %t "%r" %s %b`, `combined` adds quoted Referer and User-Agent, identical wording from 6 to 11; the shipped `server.xml` writes the expanded common pattern to `localhost_access_log.<date>.txt`; `%D` is milliseconds through 9 and microseconds from 10.1; `%T` is seconds with three decimals through 9 and whole seconds from 10.1; `%u`, `%S`, `%I` render `-` when absent; `%u` is escaped, `%I` is not; `%{UNIT}T` takes ns, us, ms, fracsec, s. Apache HTTP Server: `common` and `vhost_common` are the nicknames defined in the module doc, `combined` is the conventional name from shipped configs; `%D` microseconds, `%T` seconds, `%{UNIT}T` from 2.4.13; no thread or session token; its `%I` and `%S` are byte counts. nginx: one predefined format, `combined` (`$remote_addr - $remote_user [$time_local] "$request" $status $body_bytes_sent "$http_referer" "$http_user_agent"`), which is the `access_log` default and is byte-identical in shape to the Apache combined line; `$request_time` is decimal seconds with millisecond resolution; upstream timers may hold several comma- and colon-separated values in one token. Undertow ships `commonv` = `%h %l %u %t "%r" %s %b %T "%I"` (thread quoted). Jetty writes `%O` bytes (0, not `-`, by default) and microsecond `%D`. IIS is self-describing through a `#Fields` header. HAProxy is not CLF-shaped and signals unmeasured timers with `-1`.
- **F15 — Naming precedents.** GoAccess: `COMMON`, `COMBINED`, `VCOMMON`, `VCOMBINED`, `W3C`, `CLOUDFRONT`, …; Logstash grok: `HTTPD_COMMONLOG`, `HTTPD_COMBINEDLOG` (the `APACHE` names are deprecated aliases); lnav: one `access_log` format with internal variants; ECS field names `user.name`, `url.original`, `http.request.method`, `http.response.status_code`, `http.response.body.bytes`, `event.duration` (nanoseconds).

### Session, user, thread and filter surfaces (`ltl`)

- **F16 — The session surface is ten pieces.** Capture into `$session`; the accumulation block keyed bucket → session with a highlight twin and a found-flag, skipping empty and `-`; promotion to per-bucket `sessions` / `sessions-HL` with free-after-count; a dynamic column (`add_dynamic_column`, colour index 3, hide order 60) toggled by `-hses`; rendering through the shared secondary-metric bar; a STATS CSV column `sessions`; a YAML scalar `sessions`; a verbose oracle line in `udm-counting`; one harness assertion (`tests/validate-udm-counting.sh`); two `--help` rows and two usage rows. Separately, `-xs` makes the registry emit the `prepend_session` transform, which rewrites the message before the key is built (measured: 4 rows become 9), and fires on a bare `-` too.
- **F17 — `user` is captured by two shipped entries and consumed by nothing.** Every occurrence of the lexical is declaration, record-ref map, save/restore, self-validation or reset. `user` is nameable only as a classification-criterion field. The ThingWorx fixture's absent-user form is the empty bracket `[U: ]`; the Windchill Method Server expectations show `''` for no user; no dash sentinel is in evidence for those two producers.
- **F18 — Include, exclude and highlight match the raw line.** Code: every call site passes the line as read; the control-character normalisation record states it explicitly. Measured on the ThingWorx fixture: `-i` on a user token that appears only inside `[U: …]` includes exactly the 99 lines carrying it; `-e` drops exactly those; `-h` highlights exactly 99 and excludes none; a pattern matching only the structural marker `[O: ` (never part of the extracted message) includes all 300 lines; a session token is matchable the same way.
- **F19 — A user-defined counting metric already yields a distinct-users column** from a regex over the raw line (measured: 293 occurrences, 8 distinct on the ThingWorx fixture; users 4 beside sessions 5 on the counting fixture). It cannot name a record field, is gated on the entry capturing a message, and does not reach the heatmap or histogram. A counting metric reaches the MESSAGES CSV; the sessions column does not.
- **F20 — Highlighted sessions reach one surface.** `sessions-HL` is computed and emitted in the verbose oracle only; a highlighted run's STATS CSV gains `2xx-HL` but no `sessions-HL`; the YAML has no `sessions-HL` although the export record documents one.
- **F21 — Thread.** `$thread` feeds the thread-pool surfaces (`-tpa`, `-tpas`) and the message key (truncated to 20 characters); on access logs the thread name is therefore inside every message key.
- **F22 — Stale statements.** Two comment blocks in `ltl` and the inline comment on the match-type 3 row still say the pair "currently bind" to one slug "pending #23"; the harness scenario for the httpd specimen asserts the Tomcat slug and passes `-du us` as "the documented workaround"; `features/225-test-harness-coverage-gaps.md` carries the same row. The slug map `%match_type_to_slug` is a second, unvalidated slug source with one live read; an entry declaring a slug without a row there reports `slug: unknown` silently.

## Decisions — PROPOSED for the architect to lock

### Naming and family (R1–R4)

- **D1 — Root names are the industry names: `access_common` and `access_combined`.** `access_common` is the Common Log Format (`%h %l %u %t "%r" %s %b`; Tomcat's shipped default, Apache's default when no format is named). `access_combined` is common plus quoted Referer and User-Agent (Apache's conventional `combined`, nginx's predefined and default `combined`, Tomcat's `combined`). One pattern each; nginx and Apache combined lines are the same shape.
- **D2 — A variant name is the root plus the fields it adds, in line order.** The shapes in evidence: `access_common_duration` (common plus one trailing duration; Tomcat ≤ 9 `%D`, Tomcat ≥ 10.1 and httpd `%D`), `access_common_duration_thread_session` (common plus duration, thread name, session id), `access_common_duration_bracketed` (CodeBeamer: common plus two bracketed unit-suffixed durations, R5), `access_combined_duration` (combined plus a trailing duration, the placement Tomcat's documentation examples use). Names are the user-facing vocabulary (`-lf`, the console legend, `--help formats`, the verbose sections). *Open for the architect:* the CodeBeamer variant's suffix word (`bracketed`, `timed`, or another), and whether `access_combined_duration` ships with no specimen in the corpus (a synthetic fixture would prove it).
- **D3 — Unit is a variant-group axis, selected by provenance, and the members are named by unit.** Where one shape is written in two units by different producers (`%D` milliseconds through Tomcat 9; microseconds from Tomcat 10.1, httpd, Jetty), the members share the pattern and differ in unit, filename evidence and default, exactly as the Drop 1.5 group does today: `access_common_duration_ms` (default; Tomcat stem `localhost_access_log`, `.txt`) and `access_common_duration_us` (httpd stem `access`/`access_log`, `.log`). The same axis applies to the thread-session shape (`_ms` default, `_us`), since the same producers write it. The ambiguity note names the unit the tool assumed and the member to pin. *Alternative the architect may prefer:* producer-named members (`…_tomcat9`, `…_httpd`); rejected in this proposal because the shape is not producer-specific (R1) and the unit is the thing that differs.
- **D4 — Each shape is its own scan slot, strictly anchored, ordered specific before generic.** Every variant pattern ends at `$` and declares exactly the fields of its shape; no optional tails (F10, F11). The family is ordered longest-tail first (`thread_session`, `bracketed`, `combined_duration`, `combined`, `common_duration`, `common`) with the generic entries' `expect_ancestors` naming the specific ones, so the derived constraints and the declaration agree at build. `jboss_access` keeps its slot and ordering. Consequence: an nginx combined line binds `access_combined` and captures no session (R13); a line with a bare `-` session binds `thread_session` and the guard treats `-` as absent (R14).
- **D5 — Family membership is expressed as a `family` key on the entries, distinct from the unit `variant_group`.** The group mechanism means "one slot, members chosen by evidence" and stays that; the family means "same root, sibling shapes" and is used by the ambiguity note (which alternatives to name), `--help formats` (grouped listing) and the format-registry verbose section. *Open for the architect:* whether the family also becomes a pin operand (`-lf access_common` reading every family member) or the pin stays per name.
- **D6 — The remote-user token is captured by the prefix `([^ ]+) ([^ ]+) ([^ ]+) `**, three explicit captures, still backtracking-free, the third mapped to `user`. Capture ordinals of every field of every access entry move by two, and every `expect` record moves with them; the load-time gates prove the move. Cost is one extra assignment per matched line on the hottest path and is measured before and after (`single-day-access-log`).
- **D7 — The CodeBeamer pattern's tail is `\[(\d+(?:\.\d+)?)(us|ms|s)\] \[(\d+(?:\.\d+)?)(us|ms|s)\]`**; the first token is the duration and its unit is read from the line, so this variant carries no unit ambiguity and belongs to no unit group. The second token is matched and discarded, as today. Expected records assert the unit read from the line.

### Detection (R7)

- **D8 — Populated fields are an evidence class, added to the one weight table.** In the variant selector, the sample lines are matched with captures kept; for each candidate, each declared identity field (user, session, thread) that is populated on at least one sampled line (non-empty and not `-`) adds `field_populated` (proposed 0.5 per field, the filename-date weight; value set from the fixture outcomes at implementation). The verbose per-file evidence gains `fields: user=N/L session=N/L thread=N/L` (populated lines over sampled lines that matched the selected member) and `candidates:` shows the added credit. Rationale: with strict patterns (D4) the shape decides recognition; population is what distinguishes "the column exists" from "the column has data", which is the fact the user and session columns (D10, R11) and the analyst need, and it is the signal the architect asked for.
- **D9 — Column presence follows data, per run.** The user and session columns appear when their field was populated on at least one included line (the sessions rule today), independently of each other (R11), and each has a hide option.

### The user surface (R8–R11)

- **D10 — `users` mirrors `sessions` piece for piece.** Accumulation keyed bucket → user with a highlight twin and a found-flag, skipping empty and `-`; promotion to `users` / `users-HL` with free-after-count; a dynamic column registered beside sessions (colour index after sessions, hide order 60, so the two hide together under width pressure), `-hu` / `--hide-user`; the shared secondary-metric bar; STATS CSV column `users`; YAML scalar `users`; the verbose oracle line in `udm-counting` gains `users: N  users_hl: N`; `--help` and usage rows; `-mem` structure row. Every consumer that names `sessions` in a list (the export walk, the CSV header walk, the `-V series` description) is extended in the same commit. Applies to every entry whose field map names `user`: the three access roots' variants, `thingworx_standard`, `windchill_method_server`.
- **D11 — Filtering on the user is the raw-line filter, which already works (F18), plus nothing new.** R9 is satisfied as measured. *Open for the architect:* a field-scoped filter (`-iu <regex>` / `-eu`, matching the captured user only, the way the outcome filters select on classification) is a separate capability and is not proposed here unless asked.
- **D12 — `-xs` gains a twin `-xu` / `--expose-user`**, emitting a `prepend_user` transform on entries that capture a user, so a user can be tracked per message the way a session can. Both transforms skip empty and `-` (R14), which also fixes the `[-]` message rows.
- **D13 — Whatever is captured as a metric is exported (R12).** `sessions-HL` and `users-HL` are written to the STATS CSV (as `sessions-HL` / `users-HL`, beside the category `-HL` twins) and to the YAML export (`sessions_hl`, `users_hl` beside the plain scalars, in the export record's documented shape) whenever a highlight is active; the export record's text is trued up to what is written.

### Defects (R13–R17)

- **D14 — R13 and R14 are closed by D4, D10 and D12** (strict shapes, absent-value guards on capture and on the transforms). The nginx custom format in the corpus (F1 shape D) is not given a format of its own here; it binds `access_combined` and reads no duration, which is correct for a custom `log_format`. *Open for the architect:* whether an `access_combined_nginx_kv` variant reading `rt=` as decimal seconds is wanted in this package (the corpus has 219,933 lines of it).
- **D15 — The ambiguity note is per file and names every alternative** in the group by name and unit, once per file that fell to a default, deferred to the notices area as today. The once-per-run latch becomes per-file.
- **D16 — R17 is fixed at its cause.** The fix begins by tracing the `0us` rendering on the fractional-duration shape (F6) to the code that chooses the display unit; the specification records the cause here before the fix is written. If the cause is display scaling of sub-millisecond values, the fix is in the formatter; if it is a unit misbinding, it is in the registry.
- **D17 — Stale statements and the inventory are trued up in the same change (R16)**: the two comment blocks and the row comment (F22); the httpd harness scenario asserts the new name and drops `-du us`; the coverage-gap record's row; `docs/test-logs.md` gains the two files, says five servers, and records the shape change and the fractional duration; the `%match_type_to_slug` map either gains a build-time cross-check against the entries' slugs or is retired in favour of the entry's slug (proposal: retire; one resolution surface).

## Acceptance criteria (draft; each triaged assertable / unassertable / unknown)

Format family
- [ ] A common-format line with no trailing fields binds `access_common`; a combined line (Apache or nginx) binds `access_combined` and produces no sessions column and no duration. *Assertable* (`-V format-detection` `format:`, column header, committed fixtures).
- [ ] A common line with one trailing integer binds `access_common_duration_ms` by default, `_us` under an httpd name; the duration renders in the member's unit. *Assertable* (the Drop 1.5 fixtures re-staged under the new names).
- [ ] A common line with duration, thread and session binds `access_common_duration_thread_session_*`; a bare `-` session is not counted and not prepended under `-xs`. *Assertable* (synthetic fixture, `udm-counting` oracle, messages table).
- [ ] A CodeBeamer line with `[Nms] [N.NNNs]` and one with `[Nus] [N.NNNs]` both bind `access_common_duration_bracketed` and read the first token in the unit written on the line. *Assertable* (`-o` CSV duration, `-V format-detection`).
- [ ] `--help formats` lists the family under its root names; `-lf` accepts every new name and rejects the old ones with the list. *Assertable* (`tests/validate-help-content.sh`, format-pin scenario).
- [ ] The registry verbose section shows one slot per shape, the derived ancestors of the generic shapes naming the specific ones, and the unit groups with their occupants. *Assertable* (`tests/validate-format-registry.sh`, counts and order strings updated in the same commit).

Detection
- [ ] On a sampled file whose user column is populated, the evidence block reports `fields: user=N/L` with N > 0 and the selected member's score includes the field credit; on the same content with `-` in every user column, N = 0 and no credit. *Assertable* (two staged fixtures).
- [ ] The read-phase cost of the access family after the prefix change is within noise of before, median of three, on `single-day-access-log`. *Assertable* (before/after benchmark, gate).

User surface
- [ ] A ThingWorx file with eight distinct users in one day bucket renders a `users` column of 8 and a STATS CSV `users` of 8; the same run with `-hu` renders no column and still writes the CSV value. *Assertable* (the committed ThingWorx fixture: 8 distinct users, F19).
- [ ] A Windchill Method Server fixture with users renders the same column. *Assertable* (committed fixture, to be cut).
- [ ] An access-log fixture with populated users and sessions renders both columns side by side; a fixture with users only renders `users` only. *Assertable* (synthetic fixtures).
- [ ] A user-defined distinct metric over the user token equals the `users` column per bucket, plain and highlighted, across ≥ 2 buckets — the sessions oracle, twinned. *Assertable* (`tests/validate-udm-counting.sh`).
- [ ] `-i <user>` includes exactly the lines carrying that user in the user field; `-h <user>` highlights them and the `users-HL` column value equals the distinct highlighted users. *Assertable* (ThingWorx fixture: 99 lines for one user).
- [ ] `-xu` splits a message row per user the way `-xs` does per session. *Assertable* (messages table row counts).

Export and notices
- [ ] Under a highlight, STATS CSV and YAML carry `sessions-HL`/`users-HL` (`sessions_hl`/`users_hl`) equal to the verbose oracle; without a highlight neither key is written. *Assertable*.
- [ ] A two-file run where both files fall to a unit default prints the note twice, each naming every alternative member. *Assertable* (stderr capture).
- [ ] No ` at ltl line N` on stderr in any scenario. *Assertable* (runtime-warning check).

Visual
- [ ] The `users` bar uses the mechanism the sessions bar uses (same secondary-metric branch, same colour table) — verified by looking at rendered output on the ThingWorx specimen and an access-log specimen. *Unassertable by harness at present; verified by eye at the merge gate*, per the visual-surface rule.

Unknown (prototyping scope if the architect keeps the requirement)
- [ ] The mixed `0us`/`ms` rendering (R17): the assertion depends on the cause; the criterion is written once D16's trace is recorded.

## Prototype and measurement obligations

- Prefix change and one more capture per line (D6): a hot-path cost. Before benchmark on the base commit, after benchmark on the branch, `single-day-access-log`, medians of three. *Proposal:* no separate prototype; the change is one regex prefix and one assignment, measured through the benchmark.
