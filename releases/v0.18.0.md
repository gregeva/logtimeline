# Release v0.18.0

## What's New

- Every log line is now classified as a success or a failure under rules belonging to the detected log format — HTTP status family for access logs, log level for diagnostics logs. The run summary shows `SUCCESS CLASSIFIED` and `FAILURE CLASSIFIED` totals with their shares, the MESSAGES CSV gains `successes` and `failures` columns, and `-V format-detection` gains a `classification` sub-section and a per-file `event_ledger` property. New `--help formats` lists the known formats and their rules; new `--explain classification` explains when a success or failure percentage can be trusted. (#453)
- Access-log timelines gain success and failure percentage columns: each time bucket's share of classified requests that succeeded (green) and failed (red), rendered beside the legend. Shown by default for event-ledger formats; `-hcl`, `--hide-classification` hides them and `-scl`, `--show-classification` enables them for other classifying formats. Where a share would mislead — a bucket drawing on a format that classifies failures but not successes — the two counts are shown instead. The run summary adds an `UNCLASSIFIED` row, and the STATS CSV gains per-bucket `successes` and `failures` counts. (#452)
- Success and failure are now filter and highlight criteria. `-if`/`--include-failure`, `-ef`/`--exclude-failure`, `-is`/`--include-success` and `-es`/`--exclude-success` shift every computed statistic like the rest of the filter family; `-hf`/`--highlight-failure` and `-hs`/`--highlight-success` mark the classified subset without changing what is analysed. Excluding both leaves exactly the unclassified remainder. These short forms previously meant something else — see Breaking Changes. (#455)
- Every message row in the top-messages tables carries its classification in the consolidation marker's position: a coloured bullet in green for success, red for failure, violet for a conflict and gold for a mixed row. A line satisfying both rules is now counted as a `CLASSIFICATION CONFLICT` rather than filed as a failure, and a message row whose lines were not uniform is counted as `MIXED`. The new figures reach the run summary, the CSVs (a `conflicts` column) and the YAML export. (#456)
- Access-log formats carry industry names and are named for their shape: `access_common`, `access_combined`, `access_common_duration`, `access_common_duration_thread_session`, `access_combined_duration` and `access_common_duration_bracketed` replace the four previous Tomcat- and httpd-prefixed names, which `-lf` no longer accepts. A shape written in two units by different producers is one format read in milliseconds; `-du us` names the microsecond producers. The remote user is now captured on every access log and feeds a new `users` column of distinct users per time bucket (`-hu`/`--hide-user`, `-xu`/`--expose-user`), reaching the STATS CSV and the YAML export. (#444)
- `--explain` gains a second kind of content: named analysis techniques — the investigative moves you make with the tool — alongside the topics that explain what a figure means. Twenty-five new topics under an `ANALYSIS TECHNIQUES` heading: nineteen techniques in six groups (Time, Population, Shape, Comparison, Load, Correlation), each group also a page of its own. A technique page answers the question it addresses, shows the signal as the tool draws it, says how to read it and what would falsify the reading, and gives the worked command. `ltl --explain` lists them all; `docs/explain/techniques.md` mirrors them. (#504)
- `-o` now also writes a YAML aggregate export beside the STATS CSV: one file describing the whole analysed population with aggregates only — provenance, matched formats, the observation window, the line accounting, classification and category totals, and per time bucket every active STATS CSV column family, plus population-wide histogram percentiles under `-hg` and per-bucket heatmap percentiles under `-hm`. No message text and no per-message record, so `-n 0 -o` yields a complete description of the population with nothing per message on disk. New `-V filter-summary` reports the line accounting; `-V aggregate-export` reports what was written. (#503)
- Each category row of the run summary now shows its share of the lines included beside its count, and a horizontal bar across the row in the category's own colour. Bar length is relative to the largest category, and highlighted rows are categories in their own right, with their own share and bar. Four options adjust it: `-sbo` turns the bar off, `-sba` scales it against the lines included, `-sbl` scales it logarithmically so a rare category stays visible, and `-sbr` draws it right to left. Separately, `-sm` renders the summary table without colour. (#448)
- `-n 0` keeps no individual messages at all: nothing is stored or computed per message and the top-messages table is skipped, while the timeline and population statistics are still produced — a minimal-memory mode for very large, high-cardinality logs. A notice reports which message options have no effect. (#458)
- `-pr`/`--profile` gains eight modes: `weekday`, `weekdays`, `weekend` and `weekends`, each with an `-alt` variant for the Sunday-anchored calendar. The singular modes fold onto a single 24-hour profile, the plural ones keep each day's identity on the axis. Weekend profiling is new — nothing previously isolated Saturday and Sunday. New `--help profile` documents every mode. (#451)
- `-bs`/`--bucket-size` accepts a unit: `-bs 90s`, `-bs 1.5h`, `-bs 1d`, `-bs 0.5month` (units `ns` to `year`; a bare number still means minutes, or seconds under `-s`, or milliseconds under `-ms`). `-du`, `-ru` and the `-udm` unit slot accept the same spellings, and displayed durations now climb to weeks, months and years. (#524)
- When more than one file is selected, the progress line reports how far the whole run has got as a percentage of the bytes to be read, with the position of the file in flight (`file 12/340`). It repaints on a timer rather than on a line count, so fast input no longer floods the terminal and slow input no longer looks stalled. (#446)
- The progress line names the file in flight by its path as given, shortened in the middle when it does not fit, the same way the Processed files table does. (#532)
- The bytes metric now carries the same aggregate family as count on both CSV surfaces and as `-so` operands: `bytes_occurrences`, `bytes_min`, `bytes_mean` and `bytes_max`; a bare metric name means that metric's total. The duration statistics columns in the STATS and MESSAGES CSVs take a `duration_` prefix, while their `-so` operands keep their bare spellings and also accept it, so `-so p95` and `-so duration_p95` both work. `-so` operand names are no longer case-sensitive. The `ltl-index.csv` columns are renamed to name the metric first. (#432)
- The run summary is now printed last, after the messages table, thread-pool table, heatmap and histograms, so the analysis content is contiguous on screen. The echoed command-line options stay under the timeline. (#457)
- The category summary table shows descriptive names for HTTP status-code families — `2xx Success`, `4xx Client error`, `5xx Server error` and so on — while categories without a descriptive name keep their raw name. CSV output is unchanged. (#463)
- The legend's log level category totals are shortened (`2xx: 1.4M`), keeping the legend column from widening as message volumes grow. `-pv`, `--precise-values` restores the exact counts. (#501)
- New `-V udm-specs` section shows, for every `-udm` specification, how it was read, each compiled pattern, what the run produced for it, and any specification rejected at parse time with the reason. (#449)
- Every `--explain` topic is now introduced as what it is; the single fixed sentence that told every reader they were looking at a per-message statistic was wrong for the heatmap, histogram and classification pages. (#504)

## Bug Fixes

- The mean bytes reported for a message was understated whenever some of its lines carried no bytes value: the total was divided by every matched line rather than by the lines that actually carried bytes. On an access log mixing the two, a message's mean could read 6 bytes where the true mean was 212. `-so` ranking used the same wrong value. (#432)
- Windchill Workgroup Manager client logs written with local time are now recognised: their timestamps end in a zone offset such as `+2:00` rather than `Z`, and such a file was previously read as a ThingWorx RAC client log, keeping only the small minority of lines carrying a bracketed token. (#512)
- Control characters in a log message no longer break the messages table. A tab used to push the Occurrences cell off the line, and a carriage return or escape sequence could overwrite or re-colour the row. Tabs now render as four spaces and other control characters are removed, in the table, the CSV and the message grouping alike. (#447)
- `FATAL` log lines are now recognised and analysed. They were previously read but excluded from the results, and they count toward the error rate. (#447)
- `errRate` now counts every failure line, including highlighted ones: a highlighted 4xx/5xx or ERROR line was previously excluded from the error rate. (#453)
- Histogram and heatmap percentiles are now computed from the counters at the resolution they were captured at, rather than from the coarser representation the charts are drawn on. Percentile values, tick positions and heatmap markers move slightly and are closer to the exact answer. (#460)
- Under `-mdm bin`, the percentiles of a consolidated row no longer depend on the order its messages were combined in, and are computed from counts re-projected once rather than repeatedly. Consolidated rows' percentile and IQR values move slightly as a result. (#459)
- A run that consolidates messages (`-g`) under the bin message-stats data model now reports that consolidated rows' percentiles are approximate, and points at `-mdm raw`. (#460)
- `--help`, the options reference and `--explain percentiles` now describe what the raw and bin data models cost in accuracy, not only in memory. (#460)
- A user-defined metric that produces nothing is no longer silent: a note after the read names the spec, shows how it was read and the compiled pattern, and — when the token key contains regex characters — suggests wrapping it in slashes. A function name in the unit slot and a fixed-string pattern under `distinct` are reported at parse time. A slash-delimited regex without a capture group now yields the whole match. (#443)
- When `-so` names a statistic that no message can be ranked by, a note now says so and that the table is ordered by occurrences. The run no longer walks every message to reach that conclusion; on a 286K-message log with no durations, `-so p99` had cost 60% more statistics time than the default sort. (#418)
- A time bucket or message whose durations sum to zero rendered `0us` beside neighbours in milliseconds; a zero total now renders in the source unit. (#444)
- Notices raised while the logs are being read no longer print into the progress line, where they ran on from the progress text and were hard to read. They now appear on their own lines once reading finishes. (#446)
- A bytes metric that was never observed now reports nothing rather than zero, so a message with no bytes field is distinguishable from one whose bytes summed to zero. (#432)
- `-ob` now discards the bytes metric completely rather than continuing to capture it. (#432)
- Shortened numbers no longer carry an insignificant trailing zero: a round thousand reads `1k` rather than `1.0k`. (#501)
- Every documented `-r` example now shows the file pattern in double quotes, and the options reference explains that an unquoted pattern is expanded or rejected by the shell before `ltl` sees it. When `-r` is given and nothing matches, the failure message now says to quote the pattern. (#445)
- `-V histogram-bin-counters` now counts re-binning separately for each mechanism that causes it — partition growth, histogram combination, and the projection into display shape — replacing a single summed figure that consolidation silently reset. Member-histogram retention and footprint are reported alongside. (#462)
- `counter_memory_bytes` in `-V histogram-bin-counters` no longer varies between runs on identical input. (#461)
- `-V histogram-bin-counters` reports `members_per_partition`, the distribution of how many message histograms each row stands for. (#459)
- The histogram dimensions reported by `-V histogram-bin-counters` are now in a sub-section named `display-dimensions`, so it is clear they describe the geometry the chart is drawn on rather than the counters the section's other figures come from. (#473)
- New `-V histogram-percentile-ticks` section reports the inputs behind each histogram's percentile tick placement: the bar width, the axis range, and each percentile value at full precision. (#462)
- `-V message-grouping` now reports which message keys each consolidated cluster absorbed. (#462)

## Breaking Changes

- **Five short forms change meaning rather than failing.** Existing scripts and `LTL_CONFIG` values using them will run and do something different. To free them for the new classification criteria, the pattern-file options are renamed: `--include-file`/`-if` → `--include-pattern-file`/`-ipf`, `--exclude-file`/`-ef` → `--exclude-pattern-file`/`-epf`, `--highlight-file`/`-hf` → `--highlight-pattern-file`/`-hpf`. `--hide-session`'s short form moves from `-hs` to `-hses`, and `--include-session`/`-is` and `--include-query-string`/`-iqs` become `--expose-session`/`-xs` and `--expose-query-string`/`-xqs`. The old long names are rejected as unknown options, with no aliases; the old short forms `-if`, `-ef`, `-hf`, `-hs` and `-is` now mean the classification criteria. (#455)
- `mean_bytes` is renamed `bytes_mean`, with no alias for the old spelling. External CSV consumers and `-so` operands must update. (#432)
- The four previous access-log format names — `tomcat_access_common`, `tomcat_access_with_duration`, `httpd_access_with_duration` and `tomcat_codebeamer` — are replaced by the shape-based names above and are rejected by `-lf`. (#444)
- `-V profile` reports `profile_window_seconds`, the length of the rendered profile window, replacing `period_seconds`, which reported the internal fold period and read 604800 for the five-day work-week modes. (#451)

## Performance

Single-machine, single-run capture over the full corpus (77 test cases, both
extra-large selections included); full per-test results in
`tests/baseline/results/comparison-v0.17.0-release-vs-v0.18.0-all.md`, compared
against v0.17.0 (the prior release baseline).

Across the 63 cases both releases share, **total time is +0.2%** — unchanged —
and **peak memory is +8.4%**. The comparison file's headline "+13.3% total time"
counts the fourteen cases new to this release, not a slowdown.

## Known Issues

- **Peak memory is up 8.4% across the shared cases.** The cause is the classification work this release ships (#453, #456): every message row now carries its success, failure, conflict or mixed state, so the per-message store is wider. It shows where message cardinality is highest — `log_messages` accounts for the whole of it on the largest case, +0.97 GB of a +0.96 GB peak-RSS change — and is negligible where rows are few.
- **The `humungous-log-uniqueness` memory figure does not support a percentage.** That case read 208 MB, 255 MB, 214 MB and 264 MB across the four runs taken during this release cycle — a spread of about 50 MB between runs of identical code. The +26.8% in the table above is a single run of it.
