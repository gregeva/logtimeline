# Release v0.18.0

## What's New

- The bytes metric now carries the same aggregate family as count on both CSV surfaces and as `-so` operands: `bytes_occurrences`, `bytes_min`, `bytes_mean` and `bytes_max`. A bare metric name means that metric's total. (#432)
- `mean_bytes` is renamed `bytes_mean`, with no alias for the old spelling. (#432)
- The duration statistics columns in the STATS and MESSAGES CSVs take a `duration_` prefix. Their `-so` operands keep their bare spellings and also accept the prefix, so `-so p95` and `-so duration_p95` both work. (#432)
- `-so` operand names are no longer case-sensitive. (#432)
- The `ltl-index.csv` columns are renamed to name the metric first, and its bytes columns are prefixed `file_` to distinguish whole-file bounds from the per-message and per-time-bucket values. (#432)
- New `-V udm-specs` section shows, for every `-udm` specification, how it was read (unit, aggregation, transform, extraction method, key, source), each compiled pattern, what the run produced for it, and any specification rejected at parse time with the reason. (#449)
- The run summary is now printed last, after the messages table, thread-pool table, heatmap and histograms, so the analysis content is contiguous on screen. The echoed command-line options stay under the timeline. (#457)
- The category summary table shows descriptive names for HTTP status-code families — `2xx Success`, `4xx Client error`, `5xx Server error` and so on, with their highlighted twins — while categories without a descriptive name keep their raw name. CSV output is unchanged. (#463)
- `-n 0` keeps no individual messages at all: nothing is stored or computed per message and the top-messages table is skipped, while the timeline and population statistics are still produced — a minimal-memory mode for very large, high-cardinality logs. A notice reports which message options (`-g`, `-mdm`, `-so`, and the MESSAGES CSV under `-o`) have no effect. (#458)

- Every log line is now classified as a success or a failure under rules that belong to the detected log format (HTTP status family for access logs, log level for diagnostics logs). The run summary shows `SUCCESS CLASSIFIED` and `FAILURE CLASSIFIED` totals with their shares, the MESSAGES CSV gains `successes` and `failures` columns, and `-V format-detection` gains a `classification` sub-section and a per-file `event_ledger` property. New `--help formats` lists the known formats and their rules; new `--explain classification` explains the event-ledger property and when a reliability figure can be trusted. A format change part-way through a file is reported once per file. (#453)

## Bug Fixes

- `errRate` now counts every failure line, including highlighted ones: a highlighted 4xx/5xx or ERROR line was previously excluded from the error rate. (#453)
- `-V histogram-bin-counters` now counts re-binning separately for each mechanism that causes it — partition growth, histogram combination, and the projection into display shape — replacing a single summed figure that could not distinguish them and that consolidation silently reset. Member-histogram retention and footprint are reported alongside. (#462)
- `counter_memory_bytes` in `-V histogram-bin-counters` no longer varies between runs on identical input. (#461)
- New `-V histogram-percentile-ticks` section reports the inputs behind each histogram's percentile tick placement: the bar width, the axis range, and each percentile value at full precision. (#462)
- `-V message-grouping` now reports which message keys each consolidated cluster absorbed. (#462)
- Under `-mdm bin`, the percentiles of a consolidated row no longer depend on the order its messages were combined in, and are computed from counts that have been re-projected once rather than repeatedly. Consolidated rows' percentile and IQR values move slightly as a result. (#459)
- `-V histogram-bin-counters` reports `members_per_partition`, the distribution of how many message histograms each row stands for. (#459)
- Histogram and heatmap percentiles are now computed from the counters at the resolution they were captured at, rather than from the coarser representation the charts are drawn on. Percentile values, tick positions and heatmap markers move slightly and are closer to the exact answer. (#460)
- A run that consolidates messages (`-g`) under the bin message-stats data model now reports that consolidated rows' percentiles are approximate, and points at `-mdm raw`. (#460)
- `--help`, the options reference and `--explain percentiles` now describe what the raw and bin data models cost in accuracy, not only in memory. (#460)
- The histogram dimensions reported by `-V histogram-bin-counters` are now in a sub-section named `display-dimensions`, so it is clear they describe the geometry the chart is drawn on rather than the counters the section's other figures come from. (#473)
- Control characters in a log message no longer break the messages table. A tab in the message used to push the Occurrences cell off the line, and a carriage return or escape sequence could overwrite or re-colour the row. Tabs now render as four spaces and other control characters are removed, in the table, the CSV and the message grouping alike. (#447)
- `FATAL` log lines are now recognised and analysed. They were previously read but excluded from the results, and they count toward the error rate. (#447)
- The mean bytes reported for a message was understated whenever some of its lines carried no bytes value: the total was divided by every matched line rather than by the lines that actually carried bytes. On an access log mixing the two, a message's mean could read 6 bytes where the true mean was 212. `-so` ranking used the same wrong value. (#432)
- A bytes metric that was never observed now reports nothing rather than zero, so a message with no bytes field is distinguishable from one whose bytes summed to zero. (#432)
- `-ob` now discards the bytes metric completely rather than continuing to capture it. (#432)
- When `-so` names a statistic that no message can be ranked by — the metric was switched off with `-od`/`-ob`/`-oc`, the log carries none of it, or no message has enough values — a note now says so and that the table is ordered by occurrences. The run no longer walks every message to reach that conclusion; on a 286K-message log with no durations, `-so p99` had cost 60% more statistics time than the default sort. (#418)
- A user-defined metric that produces nothing is no longer silent: a note after the read names the spec, shows how it was read and the compiled pattern, and — when the token key contains regex characters — suggests wrapping it in slashes. A function name in the unit slot (`name:distinct:…`) and a fixed-string pattern under `distinct` are reported at parse time. A slash-delimited regex without a capture group now yields the whole match. `--help` and the options reference state that patterns match the whole raw line. (#443)
- Every documented `-r` example now shows the file pattern in double quotes, and the options reference explains that an unquoted pattern is expanded or rejected by the shell before `ltl` sees it. When `-r` is given and nothing matches, the failure message now says to quote the pattern. (#445)
