# Release v0.18.2

## Bug Fixes

- On access logs that carry a thread name, a thread written as `-` is now treated as absent: the message no longer carries a `[-]` segment. (#565)
- A counting user-defined metric (`count`, `distinct`, `ratio`, `rate`, `drate`) on a URL query-string parameter now counts that parameter's value: the value ends at `&` or `?` instead of running on through the rest of the query string. (#574)
- Message grouping (`-g`) now applies the requested sensitivity to its final pass as well. The final pass, which groups the messages the main pass leaves ungrouped, always compared messages at 85% whatever `-g` was set to, so a run at 95 still merged messages only 85% alike and a run at 70 left messages 70% alike apart. At high sensitivity the final pass is now slower on logs with many repeated messages. (#571)
- Message grouping (`-g`) now finds every partner at the requested similarity. Lines whose distinctive text is a per-request value — a signature, a signing time, a counter — were passed over by the candidate search and left ungrouped at every sensitivity; a day of signed download requests that produced no groups at all now consolidates to a handful of rows. Grouping also compares UUIDs as written instead of scoring them as one placeholder, so identifiers that differ are no longer treated as identical; where a log carries many UUIDs, masking them with `-uuid` is advisable, as they make the similarity comparison do much more work. (#569)
