# Release v0.18.2 - Fix Message Consolidation Similarity Gate

## What's New

- New: `-x <name>` / `--expose <name>` keeps a named value in the message that grouping would otherwise remove, added to the end of the message as `name=value`; repeat it for several values, which are added in the order you name them. Name the thread, session, user or query string; a metric (`duration`, `bytes`, `count`, or one of your own), whose number then stays in the message in place of `?`; or any key written in the line, such as `fileName` in a query string, which turns a day of download requests into one message per file. `-xt` names the thread and is new; `-xs`, `-xu` and `-xqs` are now shorthands for this option, and the session and user they expose are added to the end of the message instead of appearing in brackets at its front. (#566)
- New: `-m <name>` / `--mask <name>` replaces an identifier in the message with a placeholder of the same shape, so that messages differing only by that identifier become one while still showing where it sat: `uuid` gives `########-####-####-####-############`, `ipv4` gives `###.###.###.###`, `ipv6` gives `####:####:####:####:####:####:####:####` whatever the address's written length, and `ip` masks both versions; repeat the option or give a comma-separated list. Only well-formed identifiers are replaced: hexadecimal UUIDs and valid IP addresses. `-uuid` still works as the deprecated spelling of `-m uuid`, now matching hexadecimal UUIDs only, and prints a notice; its row has left `--help`. (#580)
- Deprecated: the Integration Runtime and Connection Server log formats no longer read a duration from "N milliseconds" in the message, and the number now stays in the message instead of becoming `?`; to keep reading that value, add the user-defined metric `-udm "elapsed:ms::/ (\d+) milliseconds/"`. (#576)

## Bug Fixes

- On access logs that carry a thread name, a thread written as `-` is now treated as absent: the message no longer carries a `[-]` segment. (#565)
- A counting user-defined metric (`count`, `distinct`, `ratio`, `rate`, `drate`) on a URL query-string parameter now counts that parameter's value: the value ends at `&` or `?` instead of running on through the rest of the query string. (#574)
- Message grouping (`-g`) now applies the requested sensitivity to its final pass as well. The final pass, which groups the messages the main pass leaves ungrouped, always compared messages at 85% whatever `-g` was set to, so a run at 95 still merged messages only 85% alike and a run at 70 left messages 70% alike apart. At high sensitivity the final pass is now slower on logs with many repeated messages. (#571)
- Message grouping (`-g`) now finds every partner at the requested similarity. Lines whose distinctive text is a per-request value — a signature, a signing time, a counter — were passed over by the candidate search and left ungrouped at every sensitivity; a day of signed download requests that produced no groups at all now consolidates to a handful of rows. Grouping also compares UUIDs as written instead of scoring them as one placeholder, so identifiers that differ are no longer treated as identical; where a log carries many UUIDs, masking them with `--mask uuid` is advisable, as they make the similarity comparison do much more work. (#569)
