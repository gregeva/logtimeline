# Release v0.18.1 - Packaged-binary fix for the YAML aggregate export

## Bug Fixes

- `-o` no longer fails on the downloadable binaries. Every run that wrote the YAML aggregate export died before writing it, on all platforms, reporting a missing module that was present on the machine and could not be supplied by installing it; the STATS and MESSAGES CSVs were written and the YAML was not. Introduced in v0.18.0, the first release to write the export. (#541)
- The verbose bin-counter section now reports the highlighted subset's own partitions, re-binning and counter payload beside the figures for the whole population, rather than leaving them out of the totals entirely. Both blocks appear on every run, reporting that the feature is not active when no highlight is live. (#472)
- Seven severity levels a supported log format can emit are now recognised instead of silently discarded: CRITICAL, SEVERE, WARNING, NOTICE, ALERT, EMERGENCY and AUDIT. Lines carrying them are counted and shown in the category table and the timeline, and SEVERE, ALERT and EMERGENCY join ERROR, FATAL and CRITICAL as failures under the default classification rule. The STATS CSV header lists the new levels in severity order, so a consumer reading that file by column position rather than by name needs updating. (#475)
