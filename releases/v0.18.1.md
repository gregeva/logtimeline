# Release v0.18.1 - Storage Memory Optimization, Included Library & Minor Bug Fixes

## Bug Fixes

- `-o` no longer fails on the downloadable binaries. Every run that wrote the YAML aggregate export died before writing it, on all platforms, reporting a missing module that was present on the machine and could not be supplied by installing it; the STATS and MESSAGES CSVs were written and the YAML was not. Introduced in v0.18.0, the first release to write the export. (#541)
- The verbose bin-counter section now reports the highlighted subset's own partitions, re-binning and counter payload beside the figures for the whole population, rather than leaving them out of the totals entirely. Both blocks appear on every run, reporting that the feature is not active when no highlight is live. (#472)
- Seven severity levels a supported log format can emit are now recognised instead of silently discarded: CRITICAL, SEVERE, WARNING, NOTICE, ALERT, EMERGENCY and AUDIT. Lines carrying them are counted and shown in the category table and the timeline, and SEVERE, ALERT and EMERGENCY join ERROR, FATAL and CRITICAL as failures under the default classification rule. The STATS CSV header lists the new levels in severity order, so a consumer reading that file by column position rather than by name needs updating. (#475)
- Two `-udm` metrics that share a name are no longer merged into one column. Specs differing in aggregation, transform or unit each get their own column, with the name carrying what tells them apart (`rows:sum` and `rows:delta`); specs a name cannot tell apart are reported and one is skipped, and a repeated identical spec is dropped with a notice. Previously such a pair produced one column whose numbers belonged to neither metric, could report zero for both, or could end the run with an error and no output. (#482)
- A log category a format writes but `ltl` does not recognise is now reported at the end of the run: one line per format, naming each unrecognised category and how many lines carried it, and saying those lines were not counted. Each format now declares the categories it writes — the garbage-collection pause kinds, the HTTP status families, a producer's own severity names — and `--help formats` lists them. (#476)
- In the verbose bin-counter section, a consumer that observed no value it would bin now reports that it is not active, instead of reporting the unified path over a partition set that was never built and a percentile list for percentiles that were never computed. (#546)

## Performance

- Each duration kept for the raw statistics is now retained as a number rather than as the text the log line carried, so the two duration-sample stores use about half the memory they did (peak memory down 34% on a 762,000-line access log). No figure changes, except that under `--csv-precision full` on a format writing fractional milliseconds the exported duration columns read `5` and `35.01` where the log line wrote `5.000` and `35.010`. (#561)
