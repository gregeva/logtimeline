# Release v0.18.6 - Connector and GC Formats, Explain and Histogram Fixes

## What's New

- Correct `--explain load-over-time`: a thread pool at its size is the pool's size; saturation shows as a count below demand (#652)
- Read Apache mod_jk connector logs, so connector errors sit on the timeline beside the access log's 413 and 503 responses (#655)
- Read G1 GC logs written without the level-and-tags decoration: time only, with uptime, with level, with process id (#656)

## Bug Fixes

- Fix the highlighted histogram percentile row, unreadable on a light background (`-lbg`) (#653)

## Performance

The full benchmark ran against v0.18.5 on the same machine and reads 3.0% more total time across the 77 cases, with peak memory unchanged (+0.1%). Per-case results are in `tests/baseline/results/comparison-v0.18.5-vs-v0.18.6.md`.

The difference is not in the code. The ten new log formats add about 10 ms to every run at start-up, where the known formats are built and checked, and nothing to the reading of a line: the code a line runs through is the same as in v0.18.5, a profiler reads the same time per line for both builds, and the two builds measured back to back under the same conditions are within 0.3% of each other on the same case. The 3% is the gap between two capture sessions three days apart. A user will feel the 10 ms on a short run and nothing on a long one.
