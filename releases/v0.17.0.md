# Release v0.17.0

## What's New

- Phase timing surfaces now follow the named processing stages in `stage/step` form: machine-readable `TIMING` rows read `parse/read_files`, `accumulate/initialize_buckets`, `finalize/group_similar`, `finalize/calculate_statistics`, `finalize/heatmap_statistics`, `finalize/histogram_statistics`, `render/normalize_data` (`total` unchanged), and the summary-table timing rows are stage-prefixed (`PARSE: FILE PROCESSING`, `FINALIZE: CALCULATE STATISTICS`, …); benchmark comparisons pair pre-rename TSV rows with the new labels automatically (#180)
- Log-format recognition is rebuilt on a compiled format registry with most-recently-used scan ordering, making every log type faster to read — up to 13% on access logs and 11% on mixed-format inputs — with identical output; reading a log whose duration-field unit varies across producers without `-du` now prints a one-time note naming the assumption (#58)
- Format detection now takes a read-only sample from the front, middle and end of each file (3 × 8 KB) before the file is processed, so the evidence for a file's format is drawn from the whole file rather than its first lines; what each sample saw is reported under `-V format-detection` (#388)
- Log formats that look identical but mean different things (a date written day-first vs month-first, a duration in microseconds vs milliseconds) are now told apart per file from the file name and a sample of its content; `-lf, --log-format <name>` forces a format; the summary lists the formats each file used (#384)
- New `-ni, --no-index` option: the run neither reads nor updates `ltl-index.csv`, for runs not requiring index seeding or read-back (#399)
- New `-t, --timing` option shows the per-stage timing rows in the summary; by default only `TOTAL TIME` and `MAXIMUM MEMORY USED` are printed (#400)
- New log format: Windchill Workgroup Manager (WGM) client logs (`genlwsc.log`, `uwgm_client.log`, `uwgm.log`) are recognised as `windchill_workgroup_manager`; their lifecycle message types appear as the categories `CONFIG`, `CREATE`, `DESTROY`, `START` and `FINISH` alongside the usual log levels in the timeline, legend and STATS CSV (#395)
- New log format: Windchill Method Server and Background Method Server (including the CAD and ESI workers) log4j logs are recognised as `windchill_method_server` (#396)
- The progress line shows how far through the current file the read is, as `Processing line N (P% complete) in file …`; input that cannot be sized shows the line count alone (#397)
- New `-V format-registry` section reports the log formats `ltl` knows: each entry's name and group, which variants can be told apart, the order they are tried in, and how much recognition work the run prepared (#413)
- New `-r, --recursive` option matches each file argument's filename pattern at every depth below its directory, so `-r logs/access/*.log` reads every `.log` file anywhere under `logs/access` (#420)
- The statistics phase's time is broken down in `-V benchmark-data`: sub-stage `TIMING` rows (`finalize/calculate_statistics/bucket_stats`, `population_walk`, `sort_selection`, `group_calc`, `threadpool_stats`, `untimed`) with matching element counts in `-V statistics-demand` and new `COUNTS` rows, so cost per element can be compared across runs and versions (#417)

## Bug Fixes

- Input file paths containing spaces now open correctly, with or without wildcards; previously the in-process wildcard expansion treated whitespace as a pattern separator and such paths failed with `unable to open any files` (#379)
- The v0.16.0 access-log read-phase slowdown (4–11.5% on access-log selections) is fixed: the sequential per-line pattern cascade that caused it is gone, and access-log reading is now 13.6% faster than v0.16.0 (#369)
- Day-first dates no longer abort the run with `Month out of range`; an unreadable date is reported once per file (#385)
- G1 garbage-collection logs now include the `Pause Remark` and `Pause Cleanup` pauses, plus the `To-space exhausted` and `Using G1` markers, all previously skipped (#382)
- The timestamp cache no longer grows with every distinct second in the input: it is bounded (one entry per day, capped at 100), cutting peak memory by 42% and read time by 14% on a 781k-line GC log, with identical output (#383)
- Every run no longer pays a fixed ~16 MiB of memory and ~0.1 s preparing log-format recognition it may never use: peak memory drops from 42.5 to 26.4 MiB and the preparation from 0.105 s to 0.012 s, with the work now done for the format each file actually turns out to be; `-lf` benefits the same way, and an unknown `-lf` name is reported before any of it is done (#413)
- Reading is faster on every format: the per-line log-level check no longer scans the whole level list, which had grown this release and cost non-access logs 4–6% of read time; a 100k-line ScriptLog sample reads 14% faster (#414)
