# Release v0.17.0

## What's New

- Phase timing surfaces now follow the named processing stages in `stage/step` form: machine-readable `TIMING` rows read `parse/read_files`, `accumulate/initialize_buckets`, `finalize/group_similar`, `finalize/calculate_statistics`, `finalize/heatmap_statistics`, `finalize/histogram_statistics`, `render/normalize_data` (`total` unchanged), and the summary-table timing rows are stage-prefixed (`PARSE: FILE PROCESSING`, `FINALIZE: CALCULATE STATISTICS`, …); benchmark comparisons pair pre-rename TSV rows with the new labels automatically (#180)
- Log-format recognition is rebuilt on a compiled format registry with most-recently-used scan ordering, making every log type faster to read — up to 13% on access logs and 11% on mixed-format inputs — with identical output; reading a log whose duration-field unit varies across producers without `-du` now prints a one-time note naming the assumption (#58)
- Format detection now takes a read-only sample from the front, middle and end of each file (3 × 8 KB) before the file is processed, so the evidence for a file's format is drawn from the whole file rather than its first lines; what each sample saw is reported under `-V format-detection` (#388)
- Log formats that share a line shape but differ in meaning are now told apart per file: ThingWorx Connection Server vs Integration Runtime (`yyyy-MM-dd` vs `yyyy-dd-MM` dates) and Tomcat vs Apache httpd access logs (`%D` in milliseconds vs microseconds) are separate formats selected from the file's name and a sample of its content, and re-selected mid-file if later lines prove the choice wrong; `-lf, --log-format <name>` reads every file as a named format instead of detecting it; the summary's file list shows which formats each file used, with a "Log Formats" legend; `-V format-detection` reports the evidence, candidates, selection and confidence per file (#384)

## Bug Fixes

- Input file paths containing spaces now open correctly, with or without wildcards; previously the in-process wildcard expansion treated whitespace as a pattern separator and such paths failed with `unable to open any files` (#379)
- The v0.16.0 access-log read-phase slowdown (4–11.5% on access-log selections) is fixed: the sequential per-line pattern cascade that caused it is gone, and access-log reading is now 13.6% faster than v0.16.0 (#369)
- ThingWorx Integration Runtime logs no longer abort with `Month '…' out of range`: their day-first dates are read correctly once the file is recognised as Integration Runtime, and a date that cannot be read under the selected format is reported once per file instead of ending the run (#385)
- G1 garbage-collection logs now include the `Pause Remark` and `Pause Cleanup` pauses, plus the `To-space exhausted` and `Using G1` markers, all previously skipped (#382)
